- `prototype/server/engine/events/__init__.py`: adds the merge exports.
- `prototype/server/app/events_service.py` (new): `EventService(path, clock)` with an injectable clock.
  - The `staging` table holds only the 5-minute window string per batch, never the time it arrived. Rows are deleted in the same transaction that chains them.
  - `log_state` keeps the doc rev and the highest client_seq. `snapshots` are immutable rows referenced as `snap-<id>`. `leases` holds the edit lease.
  - Closed windows are flushed at the start of every write for that log and by `flush_due()` (a hook for the future jobs tick). Checkpoint and submit force a flush.
  - Checkpoint: at most one per 5-minute window, and none without a new doc_rev. The client's `doc_hash` is stored as sent; the comparison is T-013.
  - Submit: the idempotency key is checked first, then one submit per doc_rev, then a 0-word submit is refused before anything is written. One transaction then does flush → `doc.checkpoint` → `submit`, and the seal is the hash of `submit`.
  - After the seal, `SealedError` becomes 409 `sealed`. Resubmission is `resubmit.open` (actor teacher).
  - `verify` defaults to the latest seal.
- `prototype/server/app/routes_events.py` (new): `POST /logs`, `/logs/{id}/lease`, `/lease/heartbeat`, `/batches`, `/checkpoint`, `/submit`, `/events`, `/resubmit`; `GET /logs/{id}/events`, `/verify?seal=`.
  - Every request model has `extra="forbid"`, so a client cannot send a timestamp or timing field (422).
  - `/events` accepts only the 20 client event types in `CLIENT_EVENT_TYPES`. Server-only types (`editor.batch`, `doc.checkpoint`, `submit`, `log.open`, `receipt.issued`, `resubmit.open`, …) get 422 `type_not_allowed`.
  - Errors are flat JSON: 404 `not_found`; 409 `sealed` / `rev_conflict` / `already_submitted` / `not_sealed` / `stale_client_seq` / `lease_lost` / `lease_held`; 422 `empty_submit` / `not_canonical` / `bad_batch` / `type_not_allowed`.
- `prototype/server/app/main.py`: `create_app(db_path=None, clock=None)` (`ROOM_DB_PATH`, default `:memory:`). The module-level `app`, `/healthz` and the LLM boot ping are kept.
- `prototype/server/tests/test_events_m1.py` (new, 30 tests).

## Proposed decisions (the checker takes these to the founder; nothing here is decided)
1. **Two `editor.batch` events in one window around a checkpoint.** A checkpoint (or submit) in the middle of a window forces a flush. Batches later in that same window become a second `editor.batch` with the same rounded `ts`. So the rule is "at most one per window per checkpoint segment"; since checkpoints are at most one per window, that means at most two per window. Both events carry the same `ts`, so no timing is added. *Recommend:* accept, and add this to event-log.md §5.
2. **Order in the chain within a window.** Other events (paste, quote insert, note) keep seconds and are appended when they arrive. The merged batch for a window is appended when the window closes. The chain can therefore show `editor.paste 14:03:10` before `editor.batch 14:00:00`. *Recommend:* accept; T-013 and provenance rely on marks and doc_rev, not on chain order inside a window. Say so in §5.
3. **Revision continuity is enforced at ack.** A batch carries `base_rev` and `doc_rev`; the server requires `doc_rev = base_rev + len(steps)` and `base_rev` = the current rev, otherwise 409 `rev_conflict`. A retry with `client_seq` ≤ the highest seen is a no-op only if its work is already applied; otherwise it gets 409 `stale_client_seq`, so nothing is dropped silently. *Recommend:* add `base_rev` to the batch format in event-log.md §5 (T-011/editor client must send it; ProseMirror version = step count).
4. **Checkpoint rate rule.** I read "at most one per 5 minutes of activity" as: at most one per 5-minute window, and none unless doc_rev changed since the last one. Otherwise the server answers `skipped: true` and nothing is chained. *Recommend:* confirm.
5. **Submit idempotency.** A retry with the same key returns the stored result even if the lease has expired or been taken over. The key, not the lease, identifies the request. A new key for an already-submitted doc_rev gets 409 `already_submitted` with the existing seal. *Recommend:* confirm.
6. **Word count for the 0-word block.** The server counts words from the submitted snapshot JSON (text runs split on whitespace, node boundaries count as spaces). It does not trust a client count. *Recommend:* confirm; T-014's sentence split may later share a tokenizer.
7. **Generic `/events` route.** M1 accepts 20 client event types with their payloads unvalidated. Per-type payload validation belongs to each feature task (cards, reader, Coach and so on). *Recommend:* confirm.
