## What changed
- `prototype/web/schema.json`: new. ProseMirror schema spec as JSON (`topNode`, `nodes`, `marks`), loaded by the editor and, later, by prosemirror-py (D33).
  - Nodes: `doc`, `paragraph`, `text` only (the minimum for a valid schema).
  - `origin` mark: attrs `kind` (required, closed list `typed | paste_ext | quote | helper | coach | import`) and `ref` (string or null, default null). `inclusive: false`, `excludes: "origin"` (one origin per character). `x-ref-by-kind` records which id `ref` holds for each kind, copied from the event-log.md §4 table.
  - `claim` mark: attrs `claim_id` (required string), `by` (required, closed list `student | coach | import`), `suggestion_id` (optional, default null). `inclusive: false`, `excludes: "claim"`. `x-suggestion-id-only-when-by: "student"` records the D12 rule.
  - `enum` lists and `x-` keys are ours; ProseMirror ignores them. A top-level `x-writing-room` block holds `schema_version: 1` and a pointer to the spec.
- `prototype/web/src/schema.ts`: new. `buildSchema()` / `editorSchema`: builds the ProseMirror `Schema` from the JSON and turns every `enum` + `validate` into a validate function, so a mark outside the closed list fails `Mark.fromJSON` and `node.check()`. Exports `ORIGIN_KINDS`, `CLAIM_BY`.

- `prototype/server/tests/test_schema_json.py`: new, 8 pytest tests on the raw JSON (stdlib only): closed origin list, ref-by-kind table, claim attrs, `inclusive: false`, `excludes`.

## What the schema can and cannot enforce for D21
- **Can (tested):** with `inclusive: false`, the marks a cursor inherits at any edge of a marked span (start of paragraph, end of paragraph, between two different spans, between a span and typed text) never include a non-typed origin or a claim mark. Checked with `ResolvedPos.marks()`, which is what ProseMirror uses for inserted text.
- **Cannot:** typing *inside* a marked span inherits that span's marks in plain ProseMirror. Setting `origin=typed` on every text input is the input plugin's job (event-log.md §4), which belongs to spike S1 (T-004). "Every character carries exactly one origin" is also only half schema: `excludes` gives at most one; "at least one" needs the plugin and the compile-time check.

## Proposed decisions (the checker takes these to the founder; nothing here is decided)
- **PD-1: node set.** The spec only defines marks. I shipped `doc`, `paragraph`, `text`. Essays may need headings, lists, block quotes and hard breaks; each new node changes `schema.json` and so regenerates golden logs (D33). Recommended: decide the node set in T-004 (S1) before golden logs exist, and keep it small.
- **PD-2: one claim per span.** `excludes: "claim"` means a piece of text links to at most one claim (the spec says "a `claim` mark `{claim_id, by}`", singular). If a sentence should support two claims, this must change before S1. Recommended: keep one.
