## What changed

### Engine (`prototype/server/engine/receipt/`)

- `questions.py`: `select_candidates` now returns `(chosen, more_places, skipped)`.
  - `chosen` is byte-for-byte the old selection: priority order, at most `limit` (3), at most one per paragraph, grounded only.
  - `more_places` keeps every other grounded candidate, at most one per paragraph, then sorts by `(span.from, span.to, paragraph_id)` so it is in paragraph order, never priority order.
  - Candidates without grounding are still only counted (`skipped`, law 2). The loop now walks the whole candidate list, so `skipped` counts ungrounded candidates after the first three too (PD-T027-6).
- `compile.py`: new receipt field `more_places`, built before the final wording sweep and before `receipt_hash`, so it is covered by the hash. Each item is `paragraph_id`, `span`, `why` (reason code), `why_text` (existing plain copy), `grounding` (grounding item ids), `event_ids`. No generated question text, no provider call, no `artifact_ids` (PD-T027-1, PD-T027-2).

### Web (`prototype/web/src/receipt/`)

- `types.ts`: `ReceiptMorePlace` and `Receipt.more_places`.
- `render.ts`: `renderMorePlaces` renders one `<details class="receipt-more-places">` under the questions, summarised exactly "More places to ask", closed by default. Items are an unordered list in the order supplied by the compiler, with a sentence link for the span and the existing reason text. No index, number, score or priority attribute.
- `receipt.css`: added `.receipt-more-place` to the existing print `break-inside: avoid` rule. The existing print rules and `beforeprint` handler reveal and restore all receipt disclosures, including this one.
- `review/check.mjs`: focused browser checks for the disclosure (closed, keyboard opens it, receipt-only), and per-golden count checks.
- Tests: `render.test.ts` and `gallery.test.ts`.

### Docs

- `design/receipt.md` §6: the JSON sample and the element paragraph now show and describe `more_places`; it is part of `receipt_hash`. No design/README.md row change was needed (the row already records D-060 and the date).

## Proposed decisions

- **PD-T027-1 (open point a):** extra places get **no generated question wording and no provider call**; place + existing plain reason only. Chosen as the suggested smallest option (one call per extra place would spend D-054 slots and need a second leak-checked path).
- **PD-T027-2 (open point d, field):** new receipt field is `more_places`, items `{paragraph_id, span, why, why_text, grounding, event_ids}` (integers only, no floats). Included in `receipt_hash`; the whole-list order is the compiler's paragraph order. `artifact_ids` is omitted: the list cites the place's grounding, not a generated artifact, and a non-chosen map finding therefore does not require its mapper artifact to verify. If the checker wants map-finding artifacts cited here too, add `artifact_ids` from `source_artifact_ids` and extend the verifier fixture.
- **PD-T027-3 (open point c, cap):** no cap. D-060 says every grounded candidate; the list is one item per paragraph and bounded by the document, and a cap would silently hide a place a teacher might want.
- **PD-T027-4 (open point d, schema/version):** keep `RECEIPT_SCHEMA = 1` and the receipt version semantics unchanged. The field is additive; changing `version` would create a new storage key and change release/receipt identity for no reader benefit. Existing stored receipts (without the field) are still returned unchanged.
- **PD-T027-5 (open point b, OL-059):** the student preview is not built here. The field lives only in the teacher receipt JSON; the existing student view context is tested to contain no `more_places` key or label. T-022 must not add it until OL-059 is answered.
- **PD-T027-6 (behaviour note):** `skipped_no_grounding` now counts ungrounded candidates across the whole candidate list, not only those before the first-three cut. It is still a count only; no golden receipt changes (all have zero).
